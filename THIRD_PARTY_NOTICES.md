## HEC-DSS format knowledge

The engine is an independent, clean-room Rust implementation of the HEC-DSS file formats.
Its format knowledge comes from reading HEC's
[hec-dss](https://github.com/HydrologicEngineeringCenter/hec-dss) source, which USACE HEC
distributes under the MIT licence. The format notes in `docs/format/` and comments in the code
cite the `heclib` file and function behind each rule; such citations are permitted by that
licence, and no HEC code is copied into this repository or linked into any build. HEC software
(HEC Monolith, the HEC-DSS C library, HEC-Vortex) was used only as a test oracle, outside this
repository.

## Rust dependencies

Every crate in `Cargo.lock` is listed with its SPDX expression in
[licenses/dependencies/INDEX.md](licenses/dependencies/INDEX.md), and its licence files are
retained under `licenses/dependencies/<crate>-<version>/` (`scripts/dependency_notices.py`
writes and checks them). `hdf5-core` and `netcdf-core` publish no licence file; the texts under
`licenses/upstream/` are recorded in [licenses/UPSTREAM_NOTICES.json](licenses/UPSTREAM_NOTICES.json).

The wheel carries `ras_commander_fast_dss/THIRD_PARTY_LICENSES.txt`, the licences of the
crates linked into it and the full NOTICE (`scripts/third_party_licenses.py`).

## Test data

`fixtures/public/` holds public and synthetic files only; its README gives the source of each.
Public files include HEC-DSSVue, HEC-HMS and HEC-RAS example data (USACE HEC), a sample from
the hec-dss repository (MIT), HEC-Vortex 1.1.0 test resources (MIT), and windows of public NOAA
products (MRMS, HRRR, Stage IV, WPC QPF, AORC). They are not part of the wheel or the source
distribution.

This provenance describes reuse; it does not imply endorsement by HEC, USACE or any upstream
project.
